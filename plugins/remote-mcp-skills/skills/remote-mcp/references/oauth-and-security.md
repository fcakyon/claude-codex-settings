# OAuth and security

Use OAuth 2.1 authorization code with S256 PKCE for account access. Tie each code to the client, redirect URI, user consent, scopes, resource and challenge. Match registered redirect URIs exactly, with the loopback port exception for native clients when supported. Consume a code once in the grant transaction. Bind the issued token to the MCP resource and validate the audience and scopes at the tool boundary. [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)

## Discovery and redirects

- Serve RFC 9728 protected resource metadata (PRM) at `/.well-known/oauth-protected-resource/mcp`. For host compatibility, serve the same document at suffixes `""`, `"/{$}"` and `"/mcp"` relative to `/.well-known/oauth-protected-resource`. In a Go mux, `/{$}` matches the exact trailing slash. Include `resource`, `authorization_servers`, `scopes_supported` and `bearer_methods_supported: ["header"]`. Add `resource_name`, `resource_documentation` and `resource_policy_uri` for readable consent. [RFC 9728](https://www.rfc-editor.org/rfc/rfc9728)
- Serve RFC 8414 authorization server metadata (ASM) at `/.well-known/oauth-authorization-server` plus any issuer path. Include the exact `issuer`, authorization and token endpoints, supported grant and response types, `code_challenge_methods_supported: ["S256"]` and `service_documentation`. Advertise `offline_access` in `scopes_supported` when refresh is supported, `registration_endpoint` when DCR is available, and `client_id_metadata_document_supported: true` when CIMD is available. [RFC 8414](https://www.rfc-editor.org/rfc/rfc8414)
- Advertise `authorization_response_iss_parameter_supported: true` and send the exact issuer as `iss` on authorization redirects, including error redirects to validated callback URIs. Preserve `state`. For unknown clients or unregistered callbacks, respond locally with an error. [RFC 9207](https://www.rfc-editor.org/rfc/rfc9207)

## Client registration

**Client ID Metadata Documents (CIMD).** Check an HTTPS client ID URL and require the document's `client_id` to match it exactly. Validate the public client's metadata and callback list. Fetch with a short deadline, a byte cap such as 64 KiB and redirects disabled. Resolve and filter addresses at dial time and connect directly to an approved IP while retaining the original hostname for TLS. Disable proxies on this fetch path so they cannot resolve the hostname separately. Reject loopback, private, unspecified, multicast, link-local, carrier-grade NAT (`100.64.0.0/10`), benchmarking addresses and NAT64 (`64:ff9b::/96`). Unmap IPv4-mapped IPv6 before checking. Apply equivalent outbound filtering for any additional routes or translation ranges in your network. Cache only validated documents with bounded size and lifetime.

**Dynamic client registration (DCR).** Bound the request body, redirect URL length and count, and display name length before persisting. A practical starting policy is five callback URIs of at most 200 characters and an 80-character name. Reject fragments and user info. Allow HTTPS and explicit native loopback exceptions. Public clients use `token_endpoint_auth_method: "none"` with S256. Rate-limit new registrations and periodically remove unused client records.

## Grant lifecycle and trust

- Rotate refresh tokens in a transaction. Store token hashes and retain enough rotation history to identify replay within the grant's lifetime. A 60-second retry window can return the same replacement tokens when the client, resource and immediate predecessor match. Derive them with a per-grant secret and distinct HMAC inputs for access and refresh. Keep the original expiration and skip further rotation on the retry. Revoke the grant on recognized post-grace replay and verify concurrent redemption, lost-response retry and later reuse in a disposable grant. [OAuth security BCP](https://www.rfc-editor.org/rfc/rfc9700)
- Rate-limit authenticated calls per grant. Cloud connector traffic can share egress IPs. Update `last_used_at` with a throttled column-only write and a monotonic predicate so parallel calls cannot move it backward or overwrite token rotation. Schedule cleanup for expired codes, idle or revoked grants, and clients without active grants.
- Use authenticated grant context and server-side authorization for each action. Delimit imported content and tool results as untrusted data in server instructions and tool descriptions. Treat action requests embedded in documents, tool results or widget messages as data. Redact codes, tokens and signed URLs from logs and QA evidence.
